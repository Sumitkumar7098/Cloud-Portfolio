AWS Production Architecture

Secure Multi-AZ 3-Tier Cloud Deployment

Engineered an isolated, scalable, and highly secure AWS infrastructure. Built with custom VPC networking, public web subnets with Internet Gateway routing, private compute tiers, and an isolated database tier for Amazon RDS MySQL.

  • Zero Direct DB Exposure: Database accepts connections strictly from the EC2 security group on port 3306.
  • VPC Network Segmentation: Distinct route tables for public traffic (IGW) and internal private communications.
  • Linux Server Hardening: SSH key-pair authentication, Apache web server configuration, and automated User Data scripts.
  • IAM Governance: Granular role-based policies following AWS Principle of Least Privilege.

Tier 1: Presentation & Public Ingress Tier

Public subnets, Internet Gateway routing, and entry security layers.

Internet Gateway (IGW)

Attached to custom VPC to enable bidirectional internet access for public subnets via dedicated Route Table entries (0.0.0.0/0 → igw-id).

Web Security Group

Configured stateful firewall rules allowing HTTP (port 80), HTTPS (port 443), and restricted administrative SSH (port 22) from authorized IP addresses.

Apache HTTP Server

Deployed on Amazon Linux EC2 instance serving frontend requests and communicating downstream with the application and database tiers.

Tier 2: Compute & Linux Administration Tier

Amazon Linux EC2 provisioning, SSH key pairs, and automation.

Linux System Administration

Configured Amazon Linux AMI, user accounts, systemd services, automated package updates, and secure SSH key-pair authentication.

EC2 User Data Automation

Utilized bootstrap shell scripts to automatically update OS repositories, install Apache web server, and configure runtime dependencies on instance launch.

Amazon CloudWatch Monitoring

Monitored CPU utilization, memory pressure, and network throughput with real-time metric thresholds.

Tier 3: Isolated Database & Data Storage Tier

Amazon RDS MySQL database in private subnets with strict security group chaining.

Private Subnet Placement

RDS MySQL instance deployed in completely private subnets without public IPv4 addresses, preventing direct internet access.

Security Group Chaining

Database Security Group rules configured so port 3306 accepts traffic only from the source Web/App EC2 Security Group ID (sg-xxxx).

S3 Cloud Storage & Backup

Leveraged Amazon S3 for durable object storage, web assets, and database export archives with custom IAM access policies.

AWS Cloud Security & IAM Governance

Security best practices applied across every layer of the cloud stack.

Principle of Least Privilege

Authored granular IAM policies restricting AWS API actions strictly to required resources (EC2, S3, RDS, CloudWatch).

S3 Bucket Policy Hardening

Constructed explicit JSON bucket policies to prevent unintentional public writes while enabling secure public read for static web distribution.

Alerting via AWS SNS

Integrated CloudWatch Alarms with Amazon Simple Notification Service (SNS) to deliver automated email notifications for infrastructure anomalies.
